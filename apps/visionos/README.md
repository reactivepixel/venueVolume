# Venue Volume for visionOS

A SwiftUI + RealityKit room viewer and DMX fixture prototype for visionOS 2+. The
bundled classroom is generated by `apps/room2blender`. It opens in full immersion,
accepts fixture placement on floor/table surfaces, and saves configurations locally.
No backend, downloads, physical lighting output, or paid SDK is required.

## Run

1. Open `VenueVolume.xcodeproj` in Xcode with the visionOS SDK installed.
2. Select **VenueVolume**, choose a simulator or headset, and select a signing team for a device.
3. Run and choose **Enter venue**. Room loading/validation errors appear in the floating panel.
4. Choose **Place fixture**, look at a clear floor or tabletop, and pinch. Fixtures are
   24cm cubes whose bases sit on the selected surface. Side hits and edge overhang are rejected.
5. Select a cube or name to configure its patch and channel values. Leave/re-enter or
   relaunch to restore the arrangement for that room version.

The **VenueVolume Demo** scheme opens automatically in Simulator and seeds one
instructor-desk fixture. Demo changes are temporary and never overwrite normal saves.
Existing screenshots/interface drawings depict the earlier floating-grid prototype;
they are not screenshots of this room-viewer milestone.

`project.yml` remains the project source of truth. The checked-in Xcode project includes
`VenueVolume/Environments` as a folder resource to preserve bundle-relative paths.
Regenerate with `xcodegen generate` when changing project structure.

## Coordinates, immersion and interaction

The runtime USDZ and manifest are **meters, Y-up, -Z forward**. Do not add another
Blender-axis correction in Swift. All room geometry, colliders and fixtures are children
of `VenueEnvironmentRoot`. At entry, the app aligns the manifest's floor-level spawn
and yaw to the user's initial tracked horizontal pose. It leaves tracked eye height
unchanged and keeps the room floor at the immersive space's floor origin.

Headset movement then changes the view naturally. Collision bodies do not constrain a
person's physical motion; this milestone has no joystick, teleport or navigation mesh.
Simulator uses a fixed initial floor origin/facing direction because ARKit device pose
is unavailable there. The simulator can inspect the scene but cannot prove device tracking.

The imported opaque geometry provides depth occlusion. Invisible, active entities carry
96 simplified box colliders and static physics bodies. They also receive system-targeted
spatial taps. Wall targets reject placement and block targeting a surface behind them.
Only floor/tabletop roles accept fixture placement today; collision support does not mean
wall/ceiling mounting is implemented. This is a remote virtual room, not an ARKit scan of
the wearer's current physical surroundings, and it has no real-room registration.

The room uses portable PBR materials and RealityKit's default immersive IBL. Blender
review lighting is not exported. The procedural carpet uses a documented flat-material
fallback. Photographic texture baking, room-specific IBL and lighting calibration are
future work. The room dimensions are estimated, not surveyed.

## Environment bundles and future downloads

A self-contained bundle directory currently contains:

```text
Classroom/
  environment.json
  environment.usdz
```

The pipeline also produces `environment-validation.json` and all review images alongside
these files. The app only needs the two files above. To update the bundled classroom,
copy both files from the same successful pipeline output into
`VenueVolume/Environments/Classroom/`; run Core tests and validate on a Mac before release.

`EnvironmentRepository.resolve(id:)` is the seam between content acquisition and
rendering. The shipped `DirectoryEnvironmentRepository` resolves a local directory.
`VenueScene` accepts a repository and environment ID, validates the schema and file size,
verifies SHA-256 with CryptoKit, and asynchronously loads the USDZ with RealityKit.
Loading failures keep placement disabled; leave/re-enter to retry. Unsupported schemas,
coordinate systems, malformed interaction data and checksum mismatches fail explicitly.

A future catalog/downloader should implement that same interface:

1. Fetch catalog descriptors with stable room IDs, content versions, bundle checksums and titles.
2. Download into a staging directory in Application Support, validate against a trusted catalog,
   then atomically publish an immutable cache entry keyed by room ID/version.
3. Return a `ResolvedEnvironment` with **local** file URLs. The scene needs no HTTP code.
4. Keep user placements in their separate storage directory; cache eviction must not delete them.

Authentication, remote selection UI, network retries, cache eviction and migrations between
room versions are deliberately not implemented. A checksum detects corruption; by itself
it does not authenticate a server or a manifest. Asset files and placements must remain
separate. Stable surface IDs make later migration possible, but never migrate positions
silently when geometry or coordinate origins change.

## Persistence and mock API

Every fixture includes room-local center position, quaternion orientation, scale and a
surface ID, plus its UUID, name, DMX patch and channels. Normal-mode changes are saved
atomically under Application Support `VenueVolume/Placements/<roomID>-<version>.json`.
Each new room version starts with a separate arrangement and preserves older files.
An unreadable save is preserved and disables overwriting it for that session. Save errors
are visible in the panel. This is local persistence, not shared spatial anchors or sync.

Patch validation still enforces 1–16 channels, addresses 1–512, logical universes 1–63999,
channel values 0–255, and no overlapping patch footprints. The floating inspector and
mock API failure/retry controls remain available.

`POST https://venue-volume.invalid/api/v1/dmx/configurations/sync` is intercepted by a local
`URLProtocol`; nothing is sent over the network. Schema 2 includes environment ID/version,
`coordinateSpace: environment-local-meters-y-up`, every fixture transform, channel values,
and the configuration revision. This does not emit DMX, Art-Net or sACN.

## Verification

```sh
swift test --package-path Core
xcodebuild -project VenueVolume.xcodeproj -scheme VenueVolume \
  -destination 'generic/platform=visionOS Simulator' \
  -derivedDataPath /tmp/venue-volume-derived CODE_SIGNING_ALLOWED=NO build
xcodebuild -project VenueVolume.xcodeproj -scheme VenueVolume \
  -destination 'generic/platform=visionOS' \
  -derivedDataPath /tmp/venue-volume-device CODE_SIGNING_ALLOWED=NO build
```

The shared Core tests exercise the actual shipped manifest, placement height/edge rejection,
malformed contracts, local resolution, room-version isolation, cross-store save restoration,
corrupt-save preservation, fixture validation and mock transport. Run from this repository;
the contract tests intentionally read the app's shipped bundle, not a separate fixture copy.

This milestone was checked on Linux with Swift 6.0.3 Core tests, model type checking, Swift
syntax parsing, Blender USDZ reimport and OpenUSD ARKit compatibility checks. **The modified
SwiftUI/RealityKit app has not been compiled or run with Apple's SDK here.** The successful
Xcode 27 builds recorded for the earlier grid prototype do not validate these changes.

Mac/headset acceptance checklist:

- Build both simulator and device paths; enter the classroom with correct scale/orientation.
- Confirm floor and instructor-desk fixtures rest on their surfaces; reject side/edge placement.
- Move behind a wall/pier and verify fixture occlusion and blocked input targeting.
- Edit channels, leave, quit/relaunch, and verify IDs, transforms and values are restored.
- Check corrupt/missing asset errors and leave/re-enter recovery without duplicate attachments.
- Check tracking interruption/recovery, placement input and real-device frame time/memory.
- Confirm the demo scheme leaves normal saved arrangements untouched.

Reference: [RealityKit file loading](https://developer.apple.com/documentation/realitykit/loading-entities-from-a-file),
[Apple asset optimization](https://developer.apple.com/videos/play/wwdc2024/10186/), and
[immersive environment construction](https://developer.apple.com/documentation/realitykit/construct-an-immersive-environment-for-visionos).
