# Venue chooser, wrist workflow and spatial preset UX — 2026-10-03

Integration: v0.2.3. Baseline: dev 886ede0, incorporating the preceding v0.2.2 native room validation. Work ran in `agent/ux-integration`, with owned startup, wrist and spatial-drag worktrees. Master was untouched. The implementation was followed by a source/HIG UX audit, independent code review, fixes and final native checks.

## Delivered behavior

- Normal launch presents recent saves, Load save from file and New venue. New lists Empty classroom, Empty classroom (mapped), The Fortress, plus additional library rooms. The wrist ellipsis menu uses the same chooser. Existing audit state is explicitly resumable rather than automatically entering immersion.
- Portable `.venuevolume` saves include the room asset, manifest, fixtures, referenced presets and material settings. Imports validate identity/checksum/schema and native USDZ readability before installation; cancelled or superseded imports cannot override later navigation.
- The wrist selected-item pane exposes Preset editor. Floating-label Info opens the wrist menu. Preset editors close earlier instances before opening the latest request, preserve dirty drafts and follow selection with Save/Discard/Cancel. The full item editor has one stable scene identity.
- Preset handles supply a dotted spatial tether through the input hand and a solid proposed target. Snapping uses actual fixture bounds, nearest forward ray hits, hysteresis and room occlusion; release applies exactly once. Success/error uses a white/red outline plus text/icon feedback. The Apply menu remains a gesture alternative. Applying a saved preset stops draft simulation without discarding draft edits.
- Venue immersion uses the system progressive style with range 0…1. The Digital Crown controls coverage; it does not destroy the scene. Physical Crown behavior remains untested.

## UX audit and cleanup

| Finding | Resolution or remaining review |
| --- | --- |
| P1: presets appeared after 252 fixture rows | Moved preset sources to the top of the wrist library. |
| P2: unavailable drag handle silently ignored input | Dimmed and disabled unsupported states, with a visible explanation and Apply fallback. |
| P2: repeated item-editor opens could accumulate windows | One stable selection window identity, following the active item. |
| P2: head-following interactive controls can obstruct head-pointer accessibility | Honor `accessibilityPrefersHeadAnchorAlternative`: open normal Toolbox and show targeting controls there; omit head attachments in that mode. Default head-following controls still need wearer comfort review. |
| Review: abandoned open could leave a stale room request | Request-scoped cancellation preserves Resume and cannot cancel a newer request. |
| Review: async file import could win over newer navigation | Import intent token, source-view cancellation and a final check before durable import. |
| Review: editor presenter losing ownership could strand a request | Retriable attempt identity for an unfinished request; completed/stale/timeout attempts cannot loop. |
| Review: invalid final drag sample could apply stale snap | Cancel the owning drag; focused regression tests. |
| Review: center sphere missed long fixtures and weakened wall checks | Actual AABB contact and entry distance; tests include 2.72 m tape ends and wide fixtures behind walls. |
| Review: error feedback could change with unrelated actions | Capture the error message with the feedback event. |

The audit used Apple's [spatial layout](https://developer.apple.com/design/human-interface-guidelines/spatial-layout/), [buttons](https://developer.apple.com/design/human-interface-guidelines/buttons), [drag-and-drop](https://developer.apple.com/design/human-interface-guidelines/drag-and-drop), [accessibility](https://developer.apple.com/documentation/visionos/improving-accessibility-support-in-your-app/), and [immersive experiences](https://developer.apple.com/design/human-interface-guidelines/immersive-experiences) guidance. Larger touched controls, one editor, a stationary wrist window, explicit draft decisions and non-color-only feedback improve alignment. This is not a claim of complete HIG compliance.

Remaining UX review items:

- Preset editor is fixed at 1040×820; wrist content uses a 410-point scroll area. Verify largest Dynamic Type, VoiceOver, eye-target spacing and clipped footer/error text. Fixture labels need angular legibility and overlap checks at multiple distances.
- Test indirect pinch continuation outside the window, both hands, occlusion, tracking loss, release-away cancellation and success/error feedback. Synthetic pointer samples do not establish gesture acceptance.
- Test Crown zero/full coverage, scene continuity, reopen, recenter and default head-following targeting comfort on a worn headset.
- The asset catalog and repeated preset controls remain dense. Review seated use and whether separate library tabs improve scanning after real-user testing.
- Large portable saves decode and validate on the main actor. Maximum-size import responsiveness needs profiling; cancellation prevents late mutation but does not interrupt synchronous decoding.
