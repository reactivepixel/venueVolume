# Touring inventory and programming — 2026-10-03

Release: **v0.2.6**, implemented in `agent/touring-native` from `dev` / v0.2.5 (`344e5cd`). The release integrates the touring workflow plan into the native visionOS app. `master` is unchanged. This report distinguishes model/native runtime checks from physical interaction acceptance.

## Implemented workflows

- Prepare a reusable show before entering a venue. Inventory units have stable IDs, configuration membership, preferred patches, availability and optional venue-only inclusion. Quantity-only equipment has no DMX patch. Legacy scenes opt into inventory through explicit migration.
- Place a particular available unit, drag it onto a surface, repeat placement until a model's inventory is exhausted, or preview a group row. Returning a placement preserves its equipment identity, groups and programming. Scene availability does not reserve hardware across alternative saved venues.
- Create, rename and reparent hierarchical groups; select descendants or individual units. Preview membership changes and removal, retain equipment, and block cycles. A newly added group member inherits its defaults.
- Build partial Intensity/Colour/Beam/Focus presets in the existing single editor. Apply to individual units or groups in venue/shared-show scope. Preserve exceptions when editing defaults, or replace the included parameters across all active descendants. Reject incompatible targets atomically. Preserve fixture footprints and unrelated output.
- Move/rotate a group with the existing 3D axes around its centre, or preview numeric offsets, equal X spacing, coordinate alignment and an X mirror. Auto-patch selected placements explicitly. Named focus targets solve Pan/Tilt independently for every supported fixture and remain local to a venue; moving mounts does not continuously track a target.
- Save configuration layouts, choose a configuration when opening a new venue, and preview its alignment. Save/reopen full pinned venue snapshots; export/import reusable shows independently of room geometry. Review added/removed/changed content before adopting newer shared revisions. Old venue snapshots remain reproducible.
- Preserve complete state for batch Undo/Redo. Show preparation has its own persistent journal before a room exists; venue history includes inventory, programming and multi-selection. Save/Cancel previews remain transient, and stale previews cannot overwrite later edits.

## Review and fixes

Review found and repaired two migration paths that could let touring focus definitions leak into the legacy global preset library: loading touring saves and subsequently reopening a legacy save. Regression coverage exercises both. New configurations are staged in the New venue chooser so selecting one cannot overwrite the previous venue before its Save/Discard decision.

Publishing a saved venue preset to shared-show scope now enables Save without requiring an unrelated channel edit; a regression check preserves its preset identity.

Restoring a different venue now rebinds a clean preset editor to that venue's library. Unsaved drafts survive with their stale saved identity cleared, so a venue-only preset from the second room cannot invalidate the first room's restored audit snapshot. The session regression and final three-room runtime check validate this restored state.

Other reviewed cases: parameter exclusion cannot orphan live bindings; group defaults preserve exceptions unless explicitly replaced; reset suppresses inherited individual exceptions; shared edits cannot overwrite a newer source revision; pending target state and editor updates form one Undo transaction; named-focus presets expose per-fixture solving instead of misleading shared Pan/Tilt sliders; cancelled drag leases cannot terminate a later placement session; multi-select does not accidentally invert a fixture action's target; previews validate their source revision before committing. Show/preset errors and audit failures remain visible.

The UI keeps normal movable windows, one editor, explicit button alternatives to spatial drag, standard controls with at least 60-point primary targets, scrollable forms and text-based state/error feedback. Batch Save/Cancel sits above the wrist libraries so it is not hidden below their scrolling content. Existing adaptive layout and accessibility text-size behavior are retained. This review is not a new claim of Apple HIG conformance or headset accessibility acceptance.
